4. React Core

How do you prevent unnecessary re-renders?likely
  • Keep state local; lift only when needed.
  • React.memo for pure children, useMemo/useCallback for stable props, only where profiling shows a cost.
  • Split context by concern, or use Zustand/Redux selectors so components subscribe to slices.
  • Stable keys, virtualise long lists (react-window).
  • Verify with React DevTools Profiler, not guesses.
Redux vs Context vs Zustand: when to use which?

Context: low-frequency global values (theme, auth); every consumer re-renders on change. Zustand: light global state with selector-based subscriptions, minimal boilerplate. Redux Toolkit: large apps needing predictable flow, devtools, middleware, RTK Query caching. For server data prefer TanStack Query/RTK Query over hand-rolled state.

How do you find and fix a memory leak in a React app?likely

Take heap snapshots in Chrome DevTools before and after repeated navigation; look for detached DOM nodes and growing retained objects. Common causes: uncleaned setInterval, event listeners, subscriptions, WebSockets, or closures in effects.

5. Next.js

SSR vs SSG vs ISR vs CSR: how do you choose?very likely
  • SSG: content that rarely changes (marketing, docs). Fastest, CDN-cached.
  • ISR: mostly static but updated periodically (catalogue, blog); revalidate or on-demand revalidation.
  • SSR: personalised or real-time data needing SEO (dashboards, pricing).
  • CSR: private, interaction-heavy views behind login where SEO does not matter.

Often combine them per route.

App Router vs Pages Router?

App Router uses React Server Components by default, nested layouts, streaming with loading.tsx/Suspense, server actions, and fetch caching options. Pages Router uses getServerSideProps/getStaticProps and ships more client JS. For new projects use App Router; keep Pages Router knowledge for legacy migration (incremental, both can coexist).

Server Components vs Client Components?

Server Components render on the server, can access DB/secrets, and send no JS for themselves. Add "use client" only for state, effects, or browser APIs, and push it to leaf components to keep bundles small.

How would you improve SEO and Core Web Vitals in Next.js?
  • next/image and next/font, correct priority for LCP image.
  • Metadata API, canonical URLs, sitemap, structured data.
  • Dynamic imports, remove unused JS, defer third-party scripts with next/script.
  • Avoid layout shift (reserve dimensions); cache aggressively on CDN.
Hydration errors: causes and fixes?

Server and client HTML differ: Date.now(), Math.random(), window access, invalid HTML nesting, browser extensions. Fix by moving such logic into useEffect, using suppressHydrationWarning only when justified, or rendering client-only parts with dynamic import (ssr:false).

11. API Service, Custom Hook & Error Handling

Global API service (one place for errors and response format)
// lib/apiService.ts
export class ApiError extends Error {
  constructor(public status: number, message: string, public data?: unknown) {
    super(message);
    this.name = 'ApiError';
  }
}

export type ApiResult<T> = { data: T | null; error: string | null; status: number };

const BASE_URL = process.env.NEXT_PUBLIC_API_URL ?? '';

async function request<T>(path: string, options: RequestInit = {}, timeout = 10000): Promise<ApiResult<T>> {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), timeout);
  try {
    const res = await fetch(BASE_URL + path, {
      ...options,
      signal: options.signal ?? ctrl.signal,
      headers: {
        'Content-Type': 'application/json',
        ...(localStorage.getItem('token') && { Authorization: `Bearer ${localStorage.getItem('token')}` }),
        ...options.headers,
      },
    });
    const body = res.status === 204 ? null : await res.json().catch(() => null);

    if (!res.ok) {
      if (res.status === 401) window.location.href = '/login'; // global handling
      throw new ApiError(res.status, body?.message ?? res.statusText, body);
    }
    return { data: body as T, error: null, status: res.status };
  } catch (err: any) {
    if (err.name === 'AbortError') return { data: null, error: 'Request timed out or cancelled', status: 0 };
    if (err instanceof ApiError) return { data: null, error: err.message, status: err.status };
    return { data: null, error: 'Network error. Check your connection.', status: 0 };
  } finally {
    clearTimeout(timer);
  }
}

export const api = {
  get: <T,>(p: string, o?: RequestInit) => request<T>(p, { ...o, method: 'GET' }),
  post: <T,>(p: string, body: unknown, o?: RequestInit) => request<T>(p, { ...o, method: 'POST', body: JSON.stringify(body) }),
  put: <T,>(p: string, body: unknown, o?: RequestInit) => request<T>(p, { ...o, method: 'PUT', body: JSON.stringify(body) }),
  delete: <T,>(p: string, o?: RequestInit) => request<T>(p, { ...o, method: 'DELETE' }),
};

Every call returns the same shape { data, error, status }, so components never need try/catch.

Custom hook: useFetch
// hooks/useFetch.ts
import { useCallback, useEffect, useRef, useState } from 'react';
import { api } from '@/lib/apiService';

export function useFetch<T>(url: string, immediate = true) {
  const [data, setData] = useState<T | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [loading, setLoading] = useState(immediate);
  const ctrlRef = useRef<AbortController>();

  const refetch = useCallback(async () => {
    ctrlRef.current?.abort();
    ctrlRef.current = new AbortController();
    setLoading(true);
    const res = await api.get<T>(url, { signal: ctrlRef.current.signal });
    if (ctrlRef.current.signal.aborted) return; // ignore stale response
    setData(res.data);
    setError(res.error);
    setLoading(false);
  }, [url]);

  useEffect(() => {
    if (immediate) refetch();
    return () => ctrlRef.current?.abort(); // cleanup avoids leaks
  }, [refetch, immediate]);

  return { data, error, loading, refetch };
}

Error Boundary (catches render errors)
import { Component, ReactNode } from 'react';

export class ErrorBoundary extends Component<{ children: ReactNode }, { hasError: boolean }> {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error: Error, info: unknown) {
    console.error(error, info); // send to Sentry here
  }
  render() {
    return this.state.hasError ? <h2>Something went wrong.</h2> : this.props.children;

12. JavaScript & React Hooks Basics

Hoisting

Declarations are moved to the top of their scope before execution. var is hoisted and set to undefined; let/const are hoisted but stay in the temporal dead zone until declared; function declarations are fully hoisted.

console.log(a); // undefined
var a = 5;

console.log(b); // ReferenceError (TDZ)
let b = 5;

hello();                 // works
function hello() { console.log('hi'); }

expr();                  // TypeError: expr is not a function
var expr = function () {};
Closure

A function that remembers variables from the scope where it was created, even after that scope has finished. Used for private state, memoization, and hooks.

function counter() {
  let count = 0;
  return { inc: () => ++count, get: () => count };
}
const c = counter();
c.inc(); c.inc();
console.log(c.get()); // 2

// Classic loop trap
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j)); // 0 1 2
Event loopvery likely

JS is single-threaded. The call stack runs sync code; then the microtask queue (promises, queueMicrotask) is fully drained; then one macrotask (setTimeout, events, I/O) runs, and the cycle repeats.

console.log('1 sync');
setTimeout(() => console.log('4 timeout'), 0);
Promise.resolve().then(() => console.log('3 microtask'));
console.log('2 sync');
// Output: 1, 2, 3, 4
Promises: all types
const ok = Promise.resolve(1);
const slow = new Promise(r => setTimeout(() => r(2), 100));
const bad = Promise.reject(new Error('fail'));

// all: waits for all, rejects on first failure
await Promise.all([ok, slow]);            // [1, 2]
// allSettled: never rejects, gives status of each
await Promise.allSettled([ok, bad]);      // [{status:'fulfilled',value:1},{status:'rejected',reason:Error}]
// race: first to settle (success or failure) wins
await Promise.race([slow, ok]);           // 1
// any: first to fulfil; AggregateError if all reject
await Promise.any([bad, ok]);             // 1

// Creating, chaining, async/await
const wait = ms => new Promise(res => setTimeout(res, ms));
wait(100).then(() => 'done').catch(console.error).finally(() => console.log('end'));

async function load() {
  try { return await fetch('/api'); }
  catch (e) { console.error(e); }
}

Tip: use Promise.all for independent calls to run in parallel instead of awaiting one by one.

Shallow vs deep copy

A shallow copy duplicates only the top level; nested objects are still shared. A deep copy duplicates everything.

const orig = { name: 'A', address: { city: 'Udaipur' }, tags: [1, 2] };

const shallow = { ...orig };           // or Object.assign({}, orig)
shallow.address.city = 'Jaipur';
console.log(orig.address.city);        // 'Jaipur' (shared!)

const deep = structuredClone(orig);    // modern, handles Date, Map, Set
deep.address.city = 'Delhi';
console.log(orig.address.city);        // 'Jaipur' (unchanged)

// JSON.parse(JSON.stringify(obj)) also works but loses Date, undefined, functions
// lodash: _.cloneDeep(obj)

In React/Redux state, copy only the path you change: { ...state, user: { ...state.user, name } }.

Prototype & prototype chain

Every object has an internal link to another object (its prototype). If a property is not found on the object, JS looks up the chain until null. Classes are syntax sugar over this.

function Person(name) { this.name = name; }
Person.prototype.greet = function () { return 'Hi ' + this.name; };

const p = new Person('Vijay');
p.greet();                                   // 'Hi Vijay'
console.log(p.__proto__ === Person.prototype); // true
console.log(Object.getPrototypeOf(p.__proto__) === Object.prototype); // true

class Dev extends Person {
  constructor(n) { super(n); }
  code() { return this.name + ' codes'; }
}
new Dev('A').greet(); // inherited via chain: Dev.prototype -> Person.prototype -> Object.prototype -> null
useMemo vs useCallbackvery likely

useMemo caches a computed value; useCallback caches a function reference. Both only recompute when dependencies change. Use them for expensive calculations or to keep props stable for React.memo children, not everywhere, since they have their own cost.

import { useMemo, useCallback, useState, memo } from 'react';

const Row = memo(({ item, onSelect }) => {
  console.log('render', item.id);
  return <li onClick={() => onSelect(item.id)}>{item.name}</li>;
});

function List({ items }) {
  const [query, setQuery] = useState('');
  const [selected, setSelected] = useState(null);

  // useMemo: re-filters only when items or query change
  const filtered = useMemo(
    () => items.filter(i => i.name.toLowerCase().includes(query.toLowerCase())),
    [items, query]
  );

  // useCallback: same function identity, so memoised Row does not re-render
  const handleSelect = useCallback(id => setSelected(id), []);

  return (
    <>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <ul>{filtered.map(i => <Row key={i.id} item={i} onSelect={handleSelect} />)}</ul>
    </>
  );
}

Without useCallback, a new function is created each render, so React.memo on Row would be useless.

Other quick ones: == vs ===, this, debounce
0 == '0'   // true (type coercion)
0 === '0'  // false
null == undefined // true; null === undefined // false

const obj = { n: 1, a() { return this.n; }, b: () => this.n };
obj.a(); // 1 (this = obj)
obj.b(); // undefined (arrow uses outer this)

function debounce(fn, delay) {
  let t;
  return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), delay); };
}
